# Ripple Cloud Evolution Alpha v1.2 (ground-only)

This repository package is an evolutionary **policy adapter** for an existing 8-legged 24-DOF SpiderScan digital kinematic twin. It preserves three approved legacy Python sources byte-for-byte:

- `legacy/ripple_optical_agent_LOCKED.py` — SHA-256 `7f2f611cd8f1717c3d3dcae745dbd41efc37e24315d93878231db52eaf614f77`
- `legacy/approved_kinematics_v06.py` — SHA-256 `aef18eba0520dde2e80a80d9c1e5f774bf4c355d60d879404108d21a881a4561`
- `legacy/digital_motor_v11_LOCKED.py` — SHA-256 `cce5ce28199475d8f9b063c8eb5861c5e8de02da67a1bb37df12b6d54dbad8a4`

## Model boundary

The legacy Ripple update is preserved: 
`D = 2 R + 1.2 G - 1.4 B` ; `tau_v du/dt = -u+D`; event when `u>=theta`, reset and refractory; `dtheta/dt=eta*(rate_estimate-rate_target)` (bounded).

This Alpha evolves **external gait / coupling parameters**. No optical sensor signal is generated by the RGB virtual feedback channels, which encode toe-error, rate-limit activity and target compliance. No real-world ability, robot stability, AI cognition, flying capability, or hardware skill has been demonstrated.

Candidate gene vector: stride 26–48 mm; swing 12–32 mm; cycle 1.15–2.25 s; duty .60–.82; bounded event-feedback gain 0–.55. Eight independent approved Ripple neurons feed a bounded risk adapter; no alteration of their mathematics. Evolution uses seeded elitist selection plus Gaussian mutations. Train on independent synthetic actuator regimes and evaluate on disjoint holdout conditions. A candidate passes only if it improves holdout penalty and toe error without reducing commanded-motion proxy by more than 15%. This is **not physical translation or ground contact**.

Fitness: `toe_RMS_mm + 2*max(0,33.9286 - commanded_proxy_speed_mm_s) + .025*rate_limit_hits + .2*support_proxy_loss_frames + 8*IK_failures`. Each candidate's score is `.75*mean(loss) + .25*90th-percentile(loss)` across the scenario set. This is an explicitly selected research objective, not a universal robot-performance metric.

The winning candidate's feedback gain was 0 in the first sweep, so this iteration has **no evidence that the Ripple neuron feedback caused the measured gait improvement**. The useful result is a better *simulated parameter set* for the tested scenarios.

## Run

Python 3.11+ (standard library only):

```
python -m unittest discover -s tests -q
python -m ripple_evo.evolution --out results/evolution_local.json --seed 20261013
```

`results/evolution_local.json` records exact training/holdout scenario parameters and objective trajectories. This folder includes a GitHub Actions workflow template in `docs/cloud_workflow.yml` for remote reproducibility. A template by itself is NOT evidence of cloud execution; rely on actual CI run logs for that claim.
