# Mathematical derivations and external research — Ripple v1.6

## Original sources (unchanged)

v0.1 uses normalized color drive `D=2R+1.2G-1.4B`, LIF model `tau_v du/dt=-u+D`, refractory reset and bounded adaptive threshold. The **numerical** pulses gate assignment to virtual specialists. They do not perform candidate induction and are not events measured from physical detectors.

v0.7 uses four engineering labels, each representable in two bits. The encoder is tested for source-preserved packing and unpacking. Four quaternary labels do **not** imply qubits.

v1.4 implements scalar two-slit interference, then multinomial samples photon positions according to the intensity profile. A bit is encoded as visibility `.02` vs `.98`. These are known, deliberately engineered probability distributions, not real optical measurements.

## Bayesian-style optical likelihood

For each bit `b` given photon-bin counts `n_j`, the fixed receiver computes a log-likelihood ratio

`LLR = sum_j n_j log[P(j|b=1)/P(j|b=0)]`.

For 4-bit candidate `x` define `P(x|observation)` as the normalized product of the four Bernoulli bit posterior probabilities under equal priors. For a program `f`, per-example relation evidence is

`L_f(example) = log( sum_{x=0}^{15} P_rx(x) P_ry(f(x)) )`.

Training score is the sum of these terms over **10 training examples only**, with complexity penalty `0.12 * number_of_operators` for search ranking. Its sum is **not** the log probability of a general generative model; it is a conditional compatibility score under the prescribed binary sensor likelihoods and uniform prior.

The null mapping score is `-10 log(16)` for an unknown independent uniformly distributed output nibble. We reject a candidate if its improvement over this null is less than four score units; also reject if independent three-example confirmation improvement is less than 0.7, or top-two penalized scores are separated by less than 1.5. These thresholds are engineering heuristics, not calibrated universal Bayesian posterior probabilities.

## Expansion mechanism

The initial 193 distinct functions are the original v1.5 grammar. When initial evidence is poor or ambiguous, the engine **optionally** evaluates a closed set of 135 additional functions generated by finite templates: AND/OR masks, modular odd multiplication, shifts, popcount, parity-to-mask, two-bit swap, and modular affine compositions. Equivalent 16-element truth tables are de-duplicated. No task source is executed as JS and no arbitrary data-driven primitive discovery is claimed.

The candidate mappings are deterministic functions `f:{0,...,15}->{0,...,15}`. The novelty is **relative to the v1.5 grammar**, not a claim of inventing arithmetic or a new type of computation. The held-out six inputs are never used to choose the candidate, nor are simulator truth labels used during inference.

## Experimental input reliability

For each training pair, `q_i = max_x P_rx(x) max_y P_ry(y)` and `q = mean_i q_i`. After examining the first 360-case dataset, we proposed `q >= .65` as an extra acceptance gate. We then tested that gate against seeds 555 and 666, which were not used in threshold selection. A gate is also triggered when fewer than three distinct *hard-decoded training inputs* remain.

A signal-quality gate can abstain from answer: its improved accepted-answer accuracy is **not** an improvement in total task coverage. It cannot correct a badly misspecified decoder. The 0.65 parameter is uncalibrated for a physical detector, not a NIST-style entropy-health test.

## Trace semantics

`OBSERVE -> BASELINE_SEARCH -> [GRAMMAR_EXPAND] -> TEST TRAIN -> [ABSTAIN or SUPPORTED] -> EVALUATE RESERVED` is an auditable computational decision path. This is not subjective reasoning, and the Ripple neuron contributes scheduling authorization only. Serial exhaustive search implements exactly the same numerical inference and matches the colony's results in tested conditions.

## External research and tests

- **SyGuS / Syntax Guided Synthesis:** https://sygus.org/ — formulates solutions under syntactic and semantic constraints. This project is a toy enumerative DSL rather than an industrial SyGuS solver.
- **DreamCoder:** Ellis et al., https://arxiv.org/abs/2006.08381 — learned reusable program abstractions and guided search. This Ripple program has **no learned neural search model or automatic abstraction extraction**.
- **Cryptopals public Challenge 1:** https://cryptopals.com/sets/1/challenges/1 — fixed public hex-to-base64 reference.
- **Cryptopals public Challenge 2:** https://cryptopals.com/sets/1/challenges/2 — bytewise XOR vector.
- **Cryptopals public Challenge 6:** https://cryptopals.com/sets/1/challenges/6 — specified Hamming-distance test. The external test utilities do not infer cryptographic keys, solve real ciphers or interact with wallets.
- **NIST SP 800-90B:** https://csrc.nist.gov/pubs/sp/800/90/b/final — provides rigorous entropy-source evaluation requirements. These synthetic optical observations are **not qualified entropy sources** and no NIST validation is claimed.

There is no reason to assume this specific experiment improves engineering performance on unseen byte widths, additional composition depths, arbitrary permutations, physical sensors, or unconstrained software.
