# Mathematical evidence, provenance and open verification work

Date: 2026-10-15. This register provides **traceability** for `FORMULA_REGISTRY.json` and the companion study; it does not treat every archived equation as experimentally proven.

## Evidence classes

- **LOCKED / LOCKED_OPTIONAL:** frozen or preserved numerical implementation as specified in source, not measured physical truth.
- **DERIVED / CALCULATED:** follows mathematically from declared premises. Conditions, sign conventions and units matter.
- **EXECUTED_SOFTWARE / EXECUTED_RENDER:** program code ran, including real raster renderings or numerical algorithms. Software operation is separate from calibrated physical performance.
- **SIMULATED / SYNTHETIC_TELEMETRY:** actual computed outputs from artificial, virtual or generated inputs.
- **SIMULATED_CANDIDATE / EXPERIMENTAL / RESEARCH_ALTERNATIVE:** alternate configuration evaluated in a bounded study, not automatically selected.
- **MODEL_ASSUMPTION / PROPOSED:** a model to calibrate or an unimplemented physical/computational step.
- **NEGATIVE_RESULT:** retained underperformance, absence of improvement, ambiguous outcomes or validation failure.

The earlier 56 entries retain their source labels verbatim; 44 supplemental registry entries use their version archive's provenance. Read the source document for a formula's complete test fixtures, measurement units and applicable assumptions.

## Verifiable engineering outcomes from reviewed sources

- Original v0.1: equations and exact held-drive update confirmed directly in preserved source. Continuous ODE's solution and constant-drive firing rate follow analytically.
- Mycelium v0.3: sampled hybrid controllers against original LIF using model events and synthetic workloads. Alternative gains can improve a selected rate objective; independent controls/constraints are necessary.
- Daughter Triplet v3.1: reported multiple synthetic models, no universal improvement and inconclusive colony coverage comparison; original core and Delta parent retained.
- Genetic Weights v1.7: bounded evidence transforms and new finite compositions evaluated on held-out synthetic fixtures. `phase_plus`, `phase_minus`, ternary and some prior vectors were not beneficial; serial vs Ripple-gated program inference produced the same solutions in reported paired comparisons.
- Samsung v0.4: 600 synthetic linear mixing identities. Exact arithmetic is distinct from real camera calibration.
- Samsung v0.5: 27 optical scenarios, 15 controller settings, 500 seeded noise runs and development-host timing; **no Samsung optical/power/thermal measurements**. See [Samsung study](SAMSUNG_OPTICAL_ENGINEERING.md).

## Known gaps and audit checks

1. **Archive coverage:** enumerate remaining grouped packages and embedded ZIPs, deduplicate by SHA-256, then extract equations with source file/line/version IDs.
2. **Implementation fidelity:** inspect each derived formula against the original executed source and compare parameter defaults, corner cases and discretization. An equation described in a README is not necessarily the code path that ran.
3. **Provenance granularity:** record exact source file path, commit SHA or ZIP-member hash per formula. Current supplemental registry records source ZIP names; this is sufficient for navigation but not line-level attestation.
4. **Cross-version semantics:** explicitly distinguish model-time spikes, actual device sampling frequencies, audio spectra, light intensities, pixel data, resource transport and motor position.
5. **Statistical reproducibility:** preserve inputs/seeds/metric definitions, independent holdouts, negative controls and hardware state. Re-run source tests and add independent benchmarks before claiming a stronger design.
6. **Actual Samsung verification:** calibrate camera response and gather timestamps, drift, power and thermal data on the physical device.
7. **Distribution rights:** review third-party source licenses and private Kokoro artifacts before releasing any additional binary archives or trained weights.
