Measure the engineering choices.

A reproducible experiment runner using Ripple's unchanged original neuron. Software simulations, parameter sweeps, imported camera diagnostics, and independent color-calibration holdouts are kept separate.

1. Original vs alternative optical encoders

Original [2, 1.2, −1.4] versus exploratory positive-color [1.2, 0.9, 0.7] versus linear luminance proxy 3×[0.2126, 0.7152, 0.0722]. Alternatives are proposed engineering choices, not calibrated spectral models or universal improvements.

2. Feedback-controller parameter search

Compare 15 threshold-learning combinations (five gains × three rate-estimator time constants) using the original neuron and four deterministic input protocols. Lower target error on these tests does not imply general optimality.

3. Repeated noise trials

50 reproducible software trials per encoder use synthetic jittering RGB inputs. Varying the seed changes the noise; it does not reproduce actual phone sensor noise.

4. Analyze your measured camera data

Import the actual calibration JSON exported from the Ripple phone camera panel and, when available, independent holdout observations. The four calibration references alone cannot establish predictive accuracy.

5. Analyze Samsung timing and camera stability

Use the Export camera diagnostics button in the live neuron. Timing is browser sampling cadence, not the hardware frame rate. Repeat while stationary and while lighting changes.

Measurement boundary

These numerical tests measure the software implementation. They do not establish maximum intellectual capability, biological equivalence, physical optical accuracy, camera RAW behavior, or sustained performance on the Samsung. Actual Galaxy measurements must be collected on the phone. For scientific validation, use independent reference illumination, controlled exposure, repeated captures, and a separate holdout set.

Absolute photons/wavelengths require calibrated optical instrumentation; phone RGB reports processed pixel values.
